AI20K · Day 06 · Data Lab

Hướng dẫn học viên

Đọc trang này như một tờ giấy hướng dẫn trên bàn làm việc. Không cần giỏi code trước — chỉ cần biết mình đang làm gì, mở file nào, và chạy lệnh nào.

Lab này là gì vậy?

Tưởng tượng nhóm bạn đang vận hành một dây chuyền dữ liệu mini cho AI: nhận dữ liệu → kiểm chất lượng / privacy → đưa vài mẫu “đáng nghi” cho người xem → quyết định GO (xuất), HOLD (dừng), hoặc REWORK (làm lại).

Trong 4 giờ (+ 24 giờ hoàn thiện), nhóm chọn một trong 14 challenge (T01–T14), viết phần “não” của dây chuyền, rồi chứng minh PoC của mình tốt hơn một baseline đơn giản.

Tin vui: Repo đã chuẩn bị sẵn dữ liệu giả, thước đo điểm, và nút chạy. Việc của nhóm chủ yếu nằm ở một file: src/pipeline.py.

Bản đồ thư mục (tiếng người)

Mọi thứ bạn cần đều nằm trong repo này. Chỉ cần biết mở đúng chỗ:

Quy trình làm bài — làm lần lượt

  1. Bật máy (≈ 5 phút)

    Mở terminal trong thư mục gốc của repo. Chọn đúng hệ điều hành:

    PowerShell thường không có make — dùng Python trực tiếp (cần lệnh python chạy được):

    # tạo môi trường + cài thư viện
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# kiểm tra máy sẵn sàng
.\.venv\Scripts\python.exe -m tools.preflight

# test sẵn phải 0 failed
.\.venv\Scripts\python.exe -m pytest -q

    Terminal · cần make (thường đi kèm Xcode CLT: xcode-select --install) và Python 3:

    # tạo môi trường + cài thư viện
make setup

# kiểm tra máy sẵn sàng
make preflight

# test sẵn phải 0 failed
make test

    Terminal · cần make + Python 3 (ví dụ Ubuntu: sudo apt install make python3 python3-venv python3-pip):

    # tạo môi trường + cài thư viện
make setup

# kiểm tra máy sẵn sàng
make preflight

# test sẵn phải 0 failed
make test

    Lỗi ở bước này → hỏi TA trước, chưa vội viết thuật toán.

  2. Chọn challenge + sửa config

    Nhóm thống nhất một track (ví dụ T02). Mở đề docs/tracks/T02.md, rồi sửa configs/lab.yaml:

    group_id: G07
owner: "Nguyen Van A - reviewer"
track: t02
track_config: tracks/t02.yaml
input: fixtures/t02_raw_qc

    Trong đề, chỉ cần nắm: input là gì → output file/cột gì → metric chấm thế nào → quyết định GO/HOLD nghĩa là gì.

  3. Xem dữ liệu bằng mắt

    Mở fixtures/<track>/. Có manifest.csv (danh sách file + hash) và dữ liệu input để làm bài.

  4. Chạy thử baseline để “bật đèn”

    .\.venv\Scripts\python.exe -m src.main --track t02 --pipeline src.examples.random_baseline --output out/baseline --run-name baseline --offline --seed 42
    make baseline TRACK=t02
    make baseline TRACK=t02

    Lệnh này chạy ví dụ nối dây (không phải lời giải thật). Mục tiêu: thấy output trong out/baseline/ và hiểu luồng chạy.

    Cách tự kiểm khi làm bài: mở CSV / contact sheet bằng mắt, hoặc tự gắn nhãn vài mẫu rồi so với output của nhóm. Điểm chính thức sẽ được chấm sau — lúc làm bài cứ tập trung chạy được pipeline và giải thích trong report.

  5. Viết PoC trong pipeline.py

    Đây là phần chính. Viết thuật toán ở process(), chính sách quyết định ở decide(), rồi:

    .\.venv\Scripts\python.exe -m src.main --config configs/lab.yaml --track t02 --output out/poc --run-name poc --offline --seed 42
    make run TRACK=t02
    make run TRACK=t02

    Exit 0 = chạy xong · 3 = chưa implement process() · các mã lỗi khác xem thông báo trên terminal.

    Kết quả nằm ở out/poc/.

  6. Cho người review vài mẫu “đáng nghi”

    Sau khi chạy PoC sẽ có review_queue.csv (top-B). Reviewer điền quyết định (approve / reject / edit…), lưu thành review_queue_reviewed.csv, chạy lại lệnh PoC. Hệ thống ghi audit log.

    Ý tưởng đơn giản: AI đề xuất, người kiểm chỗ rủi ro cao.

  7. So sánh baseline vs PoC + viết report

    Chạy hai lần trong cùng điều kiện (cùng data, budget, seed 42). Điền reports/group_report.md và reports/team_contributions.csv. Mỗi người nên có ít nhất một commit thật.

Năm bước pipeline — nhớ như bài hát

load→ process→ rank→ review→ decide
BướcLàm gì?Ai viết?
loadĐọc dữ liệu, kiểm file có bị đổi khôngKhung sẵn, nhóm bổ sung
processThuật toán thật sự (tính điểm, phát hiện lỗi…)Nhóm — phần quan trọng nhất
rankLấy top-B mẫu đáng xem nhất theo cột scoreCó mặc định
reviewÁp quyết định của người review + ghi nhật kýKhung sẵn, nhóm tinh chỉnh
decideGO / HOLD / REWORK + lý do + người kýNhóm viết policy

Từng click với T02 (Raw QC Triage)

Bài này đơn giản để hiểu luồng: có 96 ảnh → máy tính điểm “nghi lỗi” → đưa 20 ảnh nghi nhất cho người xem → quyết định KEEP / RECAPTURE. Làm đúng các bước dưới là chạy được end-to-end.

Một câu nhớ: Repo = đề + data + máy chạy. Nhóm chọn T02, viết não ở src/pipeline.py, chứng minh tốt hơn baseline, có người review, nộp report.

  1. Mở đề bài

    Trong Cursor / Explorer, mở file:

    docs/tracks/T02.md

    Đọc 4 ý: input images.csv + ảnh · output ranked_review.csv (cột image_id, score) · metric Defect Recall@20 · quyết định KEEP / RECAPTURE.

  2. Sửa config nhóm

    Mở configs/lab.yaml, sửa thành (đổi tên nhóm / owner cho đúng):

    group_id: G07
owner: "Nguyen Van A - reviewer"
track_config: tracks/t02.yaml
track: t02
input: fixtures/t02_raw_qc
output: out/
seed: 42
offline: true
strict_provenance: true
params: {}

    File configs/tracks/t02.yaml đã có sẵn budget: 20 — chưa cần sửa.

  3. Xem dữ liệu bằng mắt

    Mở lần lượt:

    fixtures/t02_raw_qc/images.csv
fixtures/t02_raw_qc/images/img_00_0.jpg
fixtures/t02_raw_qc/manifest.csv

    Trong CSV sẽ thấy cột image_id, path, camera_id, light, split (dev / eval).

  4. Setup máy + chạy baseline ngẫu nhiên

    Terminal đặt ở thư mục gốc của repo. Chọn đúng hệ điều hành:

    python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m tools.preflight
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m src.main --track t02 --pipeline src.examples.random_baseline --output out/baseline --run-name baseline --offline --seed 42
    make setup
make preflight
make test
make baseline TRACK=t02
    make setup
make preflight
make test
make baseline TRACK=t02

    Xong thì mở thư mục out/baseline/. Sẽ có:

    • ranked_review.csv — danh sách ảnh + score ngẫu nhiên
    • review_queue.csv — top 20
    • contact_sheet.html — mở bằng trình duyệt để xem ảnh
    • decision.json

  5. Viết PoC trong src/pipeline.py

    Mở file này — đây là chỗ nhóm “sống”. Gợi ý tối thiểu cho T02:

    Trong load() — sau phần kiểm manifest, thêm đọc bảng ảnh:

    data["images"] = pd.read_csv(ctx.input_dir / "images.csv")
return data

    Trong process() — thay raise NotImplementedError bằng vòng lặp tính điểm. Baseline đề bài gợi ý: dùng laplacian_variance (ảnh nét → số cao; ảnh mờ → số thấp). Score nghi lỗi = càng mờ càng cao, ví dụ:

    # ý tưởng — nhóm tự chỉnh / làm tốt hơn
from .common.image_ops import load_rgb, laplacian_variance, brightness_stats

rows = []
for r in data["images"].itertuples(index=False):
    img = load_rgb(ctx.input_dir / r.path)
    sharp = laplacian_variance(img)      # cao = nét
    bri = brightness_stats(img)
    score = 1.0 / (sharp + 1e-6)         # mờ → score cao
    # PoC: cộng thêm tín hiệu tối / cháy sáng…
    rows.append({"image_id": r.image_id, "score": score, "reason": "low_sharpness"})
return pd.DataFrame(rows)

    rank() mặc định đã lấy top-B theo score — thường giữ nguyên.

    Trong decide() — ví dụ policy đơn giản: nếu trong top-20 có quá nhiều ảnh nghi lỗi thì HOLD / RECAPTURE, không thì GO/KEEP. Nhớ ghi reason_code + owner.

    Chạy PoC:

    .\.venv\Scripts\python.exe -m src.main --config configs/lab.yaml --track t02 --output out/poc --run-name poc --offline --seed 42
    make run TRACK=t02
    make run TRACK=t02

    Kiểm out/poc/ranked_review.csv có đủ 2 cột image_id, score.

  6. Vòng người review (human-in-the-loop)

    1) Sau khi chạy PoC, mở out/poc/review_queue.csv (hoặc contact sheet nếu bạn render giống baseline).

    2) Reviewer điền cột quyết định (approve / reject / edit…), lưu file thành:

    out/poc/review_queue_reviewed.csv

    3) Chạy lại lệnh PoC (cùng lệnh ở bước trên).

    4) Kiểm out/poc/audit_log.jsonl và decision.json.

  7. Report + so sánh

    Điền reports/group_report.md: baseline dùng gì, PoC dùng gì, failure mode (đêm bị loại hết? glare cục bộ? cam_B mềm?). Điền reports/team_contributions.csv.

    So sánh baseline vs PoC bằng cùng data, cùng budget, cùng seed 42. Trong report ghi rõ cách nhóm tự kiểm (mắt thường / tự gắn nhãn vài mẫu / metric phụ).

    make tag-demo    # phút 180

Mấy điều đừng phá luật

Làm thật, đừng “gian lận protocol”. Chỉ dùng dữ liệu input trong fixtures/. Không tune trên split eval / heldout. Chốt threshold trước, rồi mới xem kết quả.
  • Chạy offline khi demo (--offline). Thiếu model thì báo lỗi rõ, đừng tự tải mạng.
  • Chốt threshold / trọng số trước khi nhìn kết quả đánh giá.
  • Không đưa ảnh người / biển số thật chưa có quyền lên repo công khai.
  • Không tuyên bố “đạt GDPR / luật VN” chỉ vì checklist tự động.
  • Mỗi thành viên có commit thực chất (đổi khoảng trắng không tính).
